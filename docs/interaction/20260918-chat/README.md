# 对话输入、介绍触发与页面响应修复

本轮沿用当前未提交版本，保留点位筛选、资料卡、后台媒体检索、单一语音队列和 Live2D 路径。服务地址：`http://127.0.0.1:8000`。

## 行为变化

- 不选地点也可直接说“介绍一下天津大学”或普通问题，答案写入对话。无法确定“这里”时可以直接回复名称，不要求先操作地图或目录。
- “郑东图书馆是什么？”走普通问答并记住对话地点；“进一步介绍”才启动该地点的讲解与配片。“介绍一下郑东图书馆”也可直接启动。导航、普通提及、明确说不用视频不会启动视频。
- 新的话题会清除旧的对话地点；“介绍天津大学的文化”之后继续介绍，不会误用地图仍选中的图书馆视频。
- 介绍、澄清和暂停/停止反馈都出现在对话中。讲解过程中保留输入，可继续提问、暂停、停止或查看讲解画面。
- 支持 Enter 发送、Shift+Enter 换行；输入法组字中的 Enter 不发送。草稿与流式回复分离，发送后写入的下一条草稿不会被旧任务清空。
- 请求未完成时仍可发送新问题。浏览器先取消旧流，远程取消在后台完成；旧回调不能重新写入新任务。

## 根因与修改

1. 原介绍识别器把泛化介绍归入“先选点位”。`introduction.ts` 现在区分校园话题、明确地点、当前话题追问和播放控制；`App.tsx` 的对话上下文独立于地图选择。
2. 原输入状态位于 `App`，每次敲字连同地图、行程和记录一起渲染。新增 `ChatComposer.tsx` 保存局部草稿和输入法状态。完成的回答卡片使用记忆化渲染，流式文本合并为 80ms 一次更新，无新事件时不刷新日志状态。
3. 人物层级高于对话框，可能挡住点击；窄屏 `.tour-voice` 继承了 `flex-wrap: wrap`，长记录时会把发送按钮排到窗口之外。`guide-presentation.css` 修正层级、禁止输入区域横向换列，历史单独滚动。
4. 原取消流程等待远程接口。现在本地立即中断，远程确认不阻塞新问题；异步意图处理使用代次检查。
5. VRM 渲染现在最多 30fps，输入时 20fps，后台页停止绘制，像素比上限 1.5。漫游速度按实际时间计算；手掌投影复用向量和尺寸，只在位置变化时写样式，避免每帧强制读取布局。近期记录显示上限为 40 条，并跳过屏外卡片绘制。

## 本轮验证

- `npm run build`：通过。
- `node --test --test-skip-pattern="FIXTURE" tests/ui/*.test.* tests/speech/*.test.mjs tests/interaction/*.test.mjs tests/maps/*.test.mjs`：79 项通过。
- `node --test tests/transport/*.test.mjs`：4 项通过。
- 关闭 Web 搜索运行后端 pytest：121 项通过。
- `node scripts/verify-chat-browser.mjs`：使用机器安装的 **Google Chrome 153.0.8010.48**。完整结果见 [browser-report.json](browser-report.json)。覆盖真实模型回答、真实 TTS 与本地照片导览片、介绍上下文、组字不误发送、输入草稿保留、故障注入取消接口、40 条记录，以及 1440×900、1366×768、390×844、390×500、320×568 的输入/发送/语音按钮边界和实际命中测试。

输入性能样本采用相同 Chrome、1366×768、58 次输入事件，记录输入事件到下一次动画帧的时间。可用 `node scripts/measure-chat-input.mjs after` 重新采样当前版本：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 中位数 | 7.35ms | 3.15ms |
| P95 | 11.90ms | 6.60ms |
| 最大值 | 17.40ms | 8.50ms |

原始样本：[before.json](before.json)、[after.json](after.json)、[performance-summary.json](performance-summary.json)。这是本机自动输入样本，不是所有设备的响应保证；两次短样本输入期间均未出现超过 50ms 的长任务。真实 Windows 输入法候选操作尚需人工体验，自动测试使用组合事件模拟。短窗口用于检验键盘占用空间时的布局，不代表真实手机键盘测试。本轮 Chrome 对外部高德 SDK 的访问受环境限制，地图导航沿用上轮验收结果，本轮未据此宣称在线地图重新通过。
