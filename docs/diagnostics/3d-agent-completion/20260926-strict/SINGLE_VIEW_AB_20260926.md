# 单图 TripoSR / Hunyuan3D-2mini 对照

日期：2026-09-26。目标是判断单图 Hunyuan3D 是否值得加入本地可选模型。两个提供器使用相同源图；TripoSR 指标取对应现有实跑，Hunyuan3D 使用锁定源码/权重及 fast 配置（30 步、256 分辨率、vanilla 体素解码）。单图无法验证隐藏面真实度，预览判断只用于比较可见形状与明显结构。

## 样例一：北洋园牛顿苹果树照片

输入 SHA-256：`a9b35525eb65340a7df3f493177fe5309c9ff90f7e9da7c72781220c88225ae7`。

自动分割将石碑选为主体，树木被排除；前景占比为 7.33%。因此这次对照不能评价树木重建能力，反而证实了当前主体分割是质量瓶颈。

| 指标 | TripoSR | Hunyuan3D-2mini |
|---|---:|---:|
| 端到端耗时 | 26.2 秒 | 110.3 秒 |
| CUDA 峰值显存 | 2.50 GB | 2.36 GB |
| 顶点 / 面 | 46,947 / 93,892 | 106,512 / 213,020 |
| 包围盒尺寸 | 0.929 × 0.968 × 0.183 | 1.993 × 1.983 × 0.020 |
| 观察 | 还原成石碑状厚片 | 几乎为平面石碑 |

两者都没有建出树。Hunyuan 面数更多，但厚度更差，不能把网格规模视为质量提升。

## 样例二：校园拱门照片

输入 SHA-256：`d426c54a369ce82b3115f4e469a8610e9a472822560c4a2b777eac533bef7b5d`。前景占比约 11.8%，分割目标为前景拱门；背景中的主楼不在模型范围内。

| 指标 | TripoSR | Hunyuan3D-2mini |
|---|---:|---:|
| 端到端耗时 | 14.1 秒 | 135.6 秒 |
| CUDA 峰值显存 | 2.71 GB | 2.36 GB |
| 顶点 / 面 | 43,326 / 86,648 | 321,507 / 643,080 |
| GLB 大小 | 1.73 MB | 16.72 MB |
| 几何观察 | 拱顶与开口结构明显失真 | 拱顶、柱体和多个拱形开口更完整 |
| 几何审计 | 未记录 | 3 个连通部件，非 watertight |

Hunyuan 在该样例上可见形状更好，但速度约慢 9.6 倍，网格与文件大幅增加。只有约 28.5% 的顶点获得源图直接观测颜色；反面以灰色显示。其单图补全仍不能用于测绘尺寸或证明隐藏结构。

- 已安装官方锁定版本 Hunyuan3D-2mini，权重 SHA-256 为 `3cc66f3bea33e4062b7dbc875ffe1d70c4888914aec3e91b60f94e9bd01b522b`。
- Hunyuan 现可作为本地可选单图提供器；`auto` 仍默认选择 TripoSR。自动默认没有切换，因为 Hunyuan 慢得多，且其许可与 TripoSR 不同。
- 安装器完整安装后会生成本地 `ready.json`；仅下载权重的 `--weights-only` 不会标记环境就绪。
- 两次 Hunyuan 形状推理成功生成并校验 GLB；首轮分层解码在树照片上报空批次错误，使用工作器支持的 vanilla 解码器后成功。校园拱门样例使用 vanilla 解码成功。
- 本地 API 健康检查通过；重启后状态接口报告 `providers=[triposr, hunyuan3d-2mini, depth-anything-3]`，`defaultProvider=triposr`。`git diff --check` 通过。

本地预览、输入蒙版与模型文件保存在忽略目录 `.runtime/logs/hunyuan-ab/`；不会随本报告提交。

## `torch.cat()` 空批次错误修复

此前默认的分层体素解码器在部分 256 分辨率输入上，`r257` 层没有生成任何批次，最终执行 `torch.cat([])` 并报 `expected a non-empty list of Tensors`。现将 Hunyuan 工作器默认解码器改为 vanilla。对原报错树木图片，在不传 `volumeDecoder` 参数的情况下重跑成功（82.5 秒，GLB 有效）。分层解码器仍可通过显式配置使用，但不再是默认路径。

- 主体明确：校园拱门照片。Hunyuan 生成了可辨认的拱顶、柱体和开口；这是较适合单图建模的样例。六视角预览在 `.runtime/logs/hunyuan-ab/review-views.png`，GLB 在同目录 `model.glb`。

对照原图、实际蒙版和六视角结果的拼图为 `.runtime/logs/hunyuan-ab/selected-hunyuan-preview.jpg`。查看自动蒙版有助于在耗时生成前发现主体误选。

## 建议的下一步

优先让用户确认或编辑主体蒙版，并在照片主体可能与显著前景物体不一致时提醒检查。牛顿苹果树样例表明，即使更换生成器，只要蒙版选错，最终模型仍会忠实地重建错误对象。建筑测绘继续走多视角路线，并用独立视图证据、位姿和尺度校准决定是否接受结果。

## UV 贴图优化（2026-09-26 后续）

Hunyuan 和 TripoSR 单图 GLB 先前只将输入颜色采样为顶点色，容易丢失比网格顶点间距更细的纹路。现两条单图路径都会将实际前景图投射到相机可见面并烘焙成 GLB 内嵌 UV 纹理；背面和遮挡面保留中性灰，极低可见面覆盖时回退各自旧顶点色导出。TripoSR 预处理额外保留了与建模一致的抠图 Alpha，以免把被剔除的原图背景烘进贴图。

以本报告中的校园拱门 Hunyuan shape 做离线导出验证：643,080 个三角面，UV 贴图 1296×756，纹理 GLB 18,440,464 字节（旧顶点色 GLB 16,720,420 字节，增加约 10.3%）；拟合轮廓 IoU 0.922，可见贴图面占比 28.5%，其余面仍为灰色。导出文件可重新载入为 Trimesh `texture` visual，并读回嵌入式 PNG 贴图。测试输出在 `.runtime/logs/hunyuan-ab/uv-texture-e2e/model.glb`。

TripoSR 使用同一张校园拱门照片完成本地真实推理和 GLB 导出：16.8 秒、3,240 个面、1425×1425 内嵌纹理、GLB 267,728 字节，可见贴图面占比 35.2%，轮廓拟合 IoU 0.826；文件重新载入为带 PBR 贴图和 UV 的 GLB。测试输出在 `.runtime/logs/triposr-uv-pavilion-e2e/model.glb`。

这项改变提升可见表面的颜色采样密度，不提高网格的几何精度，也不为未拍到的区域生成真实纹理。单张照片的投影视角仍由轮廓估算，细节还应对照源照片检查。现在自动选择的 TripoSR 和手动选择的 Hunyuan3D 2 mini 都会应用 UV 贴图；文字模型和多视角 DA3 暂未接入此单图投射流程。
