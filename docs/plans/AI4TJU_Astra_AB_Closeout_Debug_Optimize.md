## 四、M1：调试方法与优先排查点

每个真实问题保留一个简洁记录：`bugId、复现步骤、输入与环境、预期、实际、最小失败证据、根因或待证假设、修改位置、复验案例`。同一错误没有新证据时，不反复调用收费接口或全量重跑。

先沿最短链路定位失败在哪一层：用户事件 → 参数/意图 → 工具注册 → A/B 实现 → 服务结果 → 前端接收 → 状态更新 → 实际显示/播放。一次只验证能区分候选原因的必要假设；确认断点后再修改。避免一看到超时就更换模型或引入框架。

### 1. A/B 契约与真实工具

- 对照实际契约版本核查请求字段、枚举、工具名、参数、结果、错误、取消及回执，不为了文档同名硬改全部旧类型。
- 核查生产注册表确实调用 A 的适配器；测试夹具应保留在测试环境，不能被生产入口当成天气、官网事实、设备执行结果。
- `available` 由真实配置/能力与后端策略共同决定。`needs_permission` 必须能进入可执行的用户操作路径，不能只是一个永远等待的标签。
- pending_user_action 恢复时核对 actionId、任务、用户、设备、有效期与代际；续任务明确计数，不能用自动恢复无限重置预算。
- 工具结果不是模型写出来的成功文案。accepted/started 不等于 completed；取消请求已发出不等于底层操作已经停止。
- 文档/网页中的指令不执行；上传文件按当前用户的 uploadId 读取，来源与下载文件不能跨会话泄漏。

### 2. 讲解按钮、没有正文与没有声音

- 按真实页面操作复现，从点击处理器追踪 poiId、当前正文、语音开关、控制器状态、TTS 请求、音频 URL/类型、play() 结果与 audio 事件。
- 区分资料为空、选错点、按钮未绑定、旧闭包、语音未启用、TTS 出错、浏览器播放被拒、静音/音量、取消竞态等实际原因；只修被证据支持的分支。
- 本地已有介绍应直接显示并可供讲解，不能等联网和 GLM 生成才能出现。缺当前开放资料不应该清空基础介绍。
- 保留用户点击启动播放的有效流程；浏览器要求手势时给明确可点击入口，不能假设异步工具结果可以绕过播放限制。
- TTS 合成成功只证明音频生成；playing、可听声音、字幕推进、角色口型分别记录。没有人工听音或可用音频观察能力时，听音项标未测。
- 始终一个有效讲解会话；如果已有同步视频，保持原先静音和跟随策略。地点切换、停止和取消不能遗留旧声音、字幕或嘴形。

### 3. 点位、图片、地图与行程联动

- 同一稳定 poiId 贯穿目录、详情、图片、行程与匹配 marker；A→B→A、快速点击和迟到资料不应让界面各显示不同点。
- 图片排查真实路径、静态服务、状态码、Content-Type、解码完成、尺寸和当前选择关系。资源 HTTP 可取不等于页面已经显示；缺图占位不能算实景图通过。
- 必去/避开使用当前有效 POI 的选择项；校区切换后移除或重新确认失效选择。重复、相互冲突或跨校区不支持的选择应有明确处理。
- 路线排查起点质量/坐标系、目的地匹配、分段结果、地图就绪、路径解码、应用命令与代际。只有当前真实路径实际绘制才报告成功。
- IP 城市位置保持粗定位属性，不能未经确认当成步行起点；不存在可靠坐标时不能用示意像素或生成网格冒充。
- 普通选点保留有效路线；清空/重规划、切校区及起点失效取消相关旧请求。分开管理选点、路线、聊天、ASR 的代际，不用一个全局递增计数误杀独立任务。

### 4. GLM、RAG、时效检索与输出

- 对当前 GLM 网关做一次必要工具闭环探针，验证完整 tool_calls 参数、流式分片重组、tool_call_id 回传和结果总结。已有同构建可信记录可复用，不重复探测。
- 普通对话通过不证明原生工具/视觉/MCP 通过。兼容 JSON 模式如采用，必须明确模式并做严格白名单与 schema 校验。
- 本地 RAG 用实际命中文档、摘录与进入模型的内容证明；不要把检索模块安装成功算回答有依据。
- 官网补充保留来源、发布日期与获取日期；今天、明天按 Asia/Shanghai 解释。无当前可靠资料就明确未知，联网故障不等于官网没有答案。
- 排查 SSE 断流、工具等待、重复结束事件、来源标记泄漏、状态消息被算首字、空回答和不完整 JSON 等实际故障。
- 答案正确性主要校验事实、来源、约束与工具执行结果，不要求模型每次逐字相同。

### 5. 普通话输入和手机工具

- 使用已有录音与 ASR 服务，检查权限、真实 MIME/编码、上传解析、转写、结束录音与取消；TTS 回放样本不等于真麦克风通过。
- 普通话“暂停讲解”进入统一意图入口；排查录到自身播音引发重复触发，沿用已有 VAD/打断策略，不重建第二套语音 Agent。
- 手机文件选择、分享取消、应用不存在、设备断线均须返回真实状态；面板打开不证明消息发出，应用唤起不证明导航开始。
- 没有手机时完成适配器和桌面可验证部分，明确真机缺口；不要为了得到 PASS 临时把手机用例改成桌面模拟。

## 六、M3：基础优化升级，单项推进

核心功能修复并建立基线后，选择一个实际测到的瓶颈实施。完成并验证一项后，只有存在第二个明确瓶颈才再做一项；默认最多两项。没有测到瓶颈时，报告测量与原因，不为了凑“升级”增加改动。

可选方向（按测量选择，不要求全部做）：

| 方向 | 允许的小改动 | 必须保持的行为 |
|---|---|---|
| 点击后介绍慢 | 本地已知内容即时显示，选点/停止直达既有控制器 | 仍是当前POI，时效未知项不被旧资料替换 |
| 图片加载慢 | 现有素材按需加载、有限预取、已授权衍生缩略图、缓存/解码复用 | 原图和映射保留，清晰度可接受，缺图不串图 |
| 检索重复或串行等待 | 复用缓存/连接、同请求合并、独立只读请求有界并发 | 来源不丢、有效期正确、取消与部分失败正常 |
| 工具响应慢 | 明确意图直达、相关工具子集、缩短重复证据传输 | 保留必要证据与约束，不改变工具结果语义 |
| 地图/媒体频繁重建 | 复用marker与已有控制器、减少无效渲染/焦点抢占 | 地图、音频、字幕、角色状态一致 |
| 用户看不懂当前状态 | 修复已有按钮状态、错误提示、可取消等待与恢复入口 | 不重做布局，不增加一套独立流程 |

采用规则：

1. 写下单项假设、待测指标、正确性断言及回退点后再改代码，不要求用户逐次批准常规可逆修复。
2. 同一设备、同一输入、同一资料与配置比较。缓存冷/热分开，LLM自然波动与浏览器收益分开，不能把不同问题或不同模型混在一起。
3. 低成本页面操作可各记录三次原始值与中位数。昂贵模型/地图请求先复用本轮合法证据，不为凑统计反复收费；样本不足只报原始值，不报P95或稳定倍数。
4. 所有受影响用例继续通过才采用。性能没有明确收益、尾部恶化或正确性变差时撤回该优化，保留已经验证的bug修复；不要整体回退用户工作。
5. 需要新增错误恢复/禁用反馈等基础升级时，用真实故障分支验证。不能通过隐藏入口让失败用例消失。

正确性对照至少检查 POI 身份、事实与来源、路线起终点/分段、媒体状态、工具执行顺序及错误分支。固定录制路径可精确对照折线；实时供应商返回变化时按当次请求与服务证据核对，不能把合法更新误判为回归，也不能仅凭“都有一条线”认定一致。

至少区分以下计时：点击→正文 DOM、点击→正确图片显示、开始→audio playing、停止→媒体停止、请求→首段有效正文、请求→完整回答、路线请求→地图绘制；已启用3D另测首帧/帧时间与资源占用。

“正在思考”不是正文，TTS生成不是首音，资源下载完成不是绘制完成。没有人工听音时，audio playing只能称播放事件证据。无优化前浏览器数据就不能声称浏览器提速；必要时仅报告可测阶段的变化。

## 七、真实浏览器、设备与最终构建要求

- 优先使用当前可用浏览器工具或项目已有的浏览器测试入口。若工具列表为空，检查本地已安装浏览器与现有 Playwright/E2E 配置，尝试有依据的启动方法，不能只重复调用同一个不可用工具。
- 如果仍无法启动真实浏览器，完成可做的后端/契约/离线修复，交付可执行页面用例与最短人工步骤；页面/播放/地图项目保持 NOT_RUN 或对应阻塞，不报告全通过。
- 浏览器控制台、网络错误、页面断言、当前图像/路线和音频事件应指向同一实际构建。截图用于证明可见结果，日志用于追踪链路；二者不能互相替代所有证据。
- 最后一次涉及行为的源码修改后，必须重建受影响部分，按项目脚本重启对应实例，并对受影响主链做最终冒烟验证。较早构建的截图不能冒充最终版本。
- 记录最终 HEAD、未提交补丁指纹、前端资产标识、后端启动信息与配置/数据版本摘要；若前端由后端托管，核对服务实际返回的是新构建。
- 手机真机、桌面浏览器、合成音频、离线fixture分别报告。可选功能未启用应标 NOT_RUN/不在本轮范围，不计作全部失败，也不计作通过。

## 八、调用预算与停止条件

两种预算分开：Astra 开发验证的工作过程，与产品每次 GLM 任务的运行预算不同。不要用产品“两次模型请求”的限制阻止开发调试本身，但实际外部服务调用必须记账。

产品普通任务沿用已约定上限：默认2次GLM、6次工具、45秒总期限；检索子期限默认3.5秒并服从剩余期限。已有更严格限制优先。首次计划中的可解析依赖由程序执行；需要新判断而超预算时返回部分结果和继续入口，不偷偷增加循环。不要通过优化擅自放宽这些限制。

本轮真实验收优先沿用当前可用且已授权的预算；没有配置时先使用保守上限：GLM 8次、TTS 2次、POI查询4次、真实步行2次、搜索4次、页面抓取8次、视觉模型0次。它们是整轮上限，不是必须耗尽的目标；内部请求也计入已知数量，供应商内部不可见重试如实说明。已配置真实ASR按必要三句验证，避免长期录音或重复压测。

到预算上限后继续离线分析、录制响应重放和不调用外部服务的修复；需要新请求才能确认的项目标明待验，不通过重跑脚本绕过上限。普通话命令、导出和固定讲解优先复用已有服务结果。

同一失败没有新线索不无限重试；资源不足、设备不在、凭证失效或供应商不可用时保存具体证据，转向仍能推进的任务。停止条件是适用主链已验证、必要回归通过、优化有依据且未退化，或剩余项具有明确外部阻塞。不要停在仅写报告或仅接口200。

## 九、最终交付与答复格式

复用现有诊断目录；需要新目录时使用 `docs/diagnostics/ab-closeout/<实际运行标识>/`。将相关产物集中，避免散落重复报告。

至少交付：

1. `report.md`：本轮实际范围、根因与修复、旧功能保护结果、最终状态、残留问题和回退方式。
2. `cases.jsonl` 与 `results.jsonl`：关联原H/A/B编号、输入、断言、结果与证据；已有等价文件可直接追加。
3. `performance.json`：修复后基线与优化后原始值、设备/构建/缓存条件、采纳或撤回结论。未测项留空并说明，不填估算数。
4. 最小证据目录与最终构建记录：必要截图、trace、错误日志、实际调用账本；脱敏，不保存凭证。
5. 本轮增量diff/补丁与新增文件清单，明确适用基线及如何检查回退；不能把用户原改动纳入自动回退。

结果标签沿用 PASS_REAL（同时标明页面/服务/音频事件/人工听音/真机范围）、PASS_OFFLINE、FAIL、NOT_RUN、BLOCKED_CONFIGURATION。无法打开浏览器之类的环境阻塞另写 reason；状态不能代表未观察到的能力。

最终答复按以下顺序，保持简洁：

- **现在能用什么：** 明确具体任务及证据范围。
- **修复了什么：** 列主要故障、根因、最小修改和复验结果。
- **旧功能是否保住：** 哪些与基线一致，哪些尚未证明；不能只报测试总数。
- **优化是否有效：** 分离bug修复收益与M3性能收益，给原始数据位置与限制。
- **如何运行与查看问题集：** 实际命令、地址、文件绝对路径及五步以内人工验收。
- **剩余项：** 实现缺陷、配置/设备阻塞、可选未启用分开列。仍有核心失败时不要说整体收尾完成。
