# 轻量查询与响应框架（待本地实现）

这是供 `E:\AI4TJU` 本地 Codex 接入的设计和配置，不是已运行的服务。与 `local_task_prompts.md` 合并执行；来源入口见 `source_registry.json`，参数见 `retrieval_policy.json`。沿用 FastAPI、当前 GLM 客户端、RAG、地图和单一语音控制器；已有 LangGraph 才复用，否则用类型明确的函数组织流程。

## 1. 查询流程

`请求校验 → 本地检索/缓存 → 按需官网查询 → 按问题类型启用备用来源 → 证据筛选 → 一次回答生成 → 流式返回`。

选点、图片和有充分本地事实的固定讲解走快路径，零模型、零联网。普通回答最多一次 GLM 生成；确需模型选择工具时最多两次 GLM 调用，禁止逐站串行生成行程介绍。网关不支持 tool calling 时，用后端意图分流实现同等功能，不把普通文本伪称工具调用。

最小职责划分：`IntentRouter` 校验校区、POI 和约束；`EvidenceRetriever` 并发读本地/网页；`EvidenceFilter` 检查实体、来源和时效；`AnswerComposer` 组织已有事实和模型结果；`EventPublisher` 发送现有流式事件。这些是服务内模块，不是五个独立 Agent。

模型只能选注册工具和来源。官方层内允许按相关性查其他官方来源；官方未命中后，文化介绍、经验建议才可进入已配置的补充层；当天入校、开放、闭馆等只能用适用官方依据确认。社区经验单独标注，转载不计作独立证据。不得将“没搜到”推成“没有限制”。网页是资料，不是指令；校验跳转后的来源域名。

## 2. 时间和调用边界

默认程序分流；可选模型工具选择发生在联网阶段前。联网检索阶段开始时建立3500ms截止时间，包含搜索、排队、取页与提取，并受请求开始起45000ms的整体截止时间限制；第二轮只使用剩余时间，轮间不插入模型思考。前面的本地读取和模型选择仍计入整体耗时。单来源最多 1500ms，总并发3、单域名2；最多2轮、2次搜索、4次页面读取，缓存未命中的实际外部请求计数，失败也计入。默认无应用层失败重试。

整个回答45000ms包含检索与模型，是查询回答资源截止时间，不是提速成绩；音频播放、用户录音和地图任务按各自生命周期测量。8秒仍无正文时显示确有依据的本地内容和独立查询状态，提供取消；没有有据正文时只显示状态，不能将状态、占位文字或首个SSE事件计作有效首正文。

所有等待、排队、取页和生成传递取消与剩余预算。截止后不启动新调用，尽力终止在途请求；供应商已接受调用未必停止计费，日志如实区分。

## 3. 缓存和请求合并

建议TTL：稳定资料86400秒、新闻300秒、当前规则60秒；TTL只是刷新策略，不保证公告适用当天。过期动态资料保留日期并标为待重新核验，不作为今日已确认规则。

缓存键包含校区、POI、意图、上海时区查询日期、规范化查询约束、资料版本；另纳入查询文本和来源范围，不能仅按相同问句共用。必去/避开集合数组排序后入键，真实路线站点序列保留顺序；不得跨校区共用含糊名称结果。

失败仅进入15秒冷却，不存作 `no_evidence`。成功完成指定查询但无证据可存30秒负缓存，严格保留查询范围。相同完整键用 singleflight 合并；一个用户取消只取消其订阅，最后消费者退出后才尝试取消共享请求。

## 4. 契约与页面状态

每个事件至少有 `channel/requestId/generation/seq/campusId/poiId/routeId/type`，不适用的地点或路线ID允许null。客户端只接收当前请求、当前代际且seq递增的事件。地点、聊天、路线、ASR各自维护代际；更换地点只取消相关详情/讲解，不误取消仍有效的路线请求。重规划、清空、校区变化或使当前请求失效的起点变化更新路线代际，普通选点不更新；普通浏览其他地点不得清除已确认路线。

查询状态：`success` 有足够依据；`partial` 仅部分问题有依据或查询未全部完成；`no_evidence` 本次指定查询成功但无可用证据；`timeout/unavailable/cancelled/error` 分别为超时、能力未配置、取消及其他失败。复合问题逐部分标状态，不能一条历史事实掩盖今日规则核验失败。

每条网页证据记录 `sourceId/registryId/title/url/finalUrl/publishedAt/validFrom/validTo/fetchedAt/provenance/poiIds/campusId`，未知日期为null。`publishedAt`来自正文或可信页面元数据，不能拿搜索索引抓取日期代替。registryId对应站点注册表，sourceId对应具体文档证据，二者不能混用。保留文章来源、转载关系和检索方式；答案引用只允许实际证据ID。

行程状态独立使用 `draft/route_pending/ready/partial/failed`。`ready`要求约束满足、所需路径真实可用并收到当前地图应用确认；总时长尚不完整就不能保证满足时间预算。浏览器绘制状态由前端回执提供，模型不能宣布绘图成功。

## 5. 集成与验收

开始讲解不等联网，直接使用当前已核实文本；停止和切点须取消旧声音、队列与迟到结果。联网补充不自动抢播。图片继续使用现有映射；录音识别成可编辑文本后才由用户发送。必去/避开提交稳定ID并在调用模型前校验。

保留 `questions.md` 的真实播放、地图DOM和普通话ASR验收。新增：官网无依据后合规备用命中；旧公告与当前规则冲突；快切点/换校区与缓存隔离；截止与取消不启动额外请求；冷/热缓存分别记录有效首正文和完整完成时间。检查最后一个共享请求订阅者取消才中止上游。

记录本地检索、搜索、取页、模型首正文、有效内容首次可见及总耗时，同时记录调用数、失败和降级。固定样本3次报告原始值与中位数；状态提示不能当加速，HTTP200不能代替播放或地图实际显示。最终报告明确本地代码是否接入、哪些供应商真实可用、哪些页面仍待验。
