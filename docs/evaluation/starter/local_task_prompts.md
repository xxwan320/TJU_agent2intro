## 1. 修好当前地点的介绍和开始/停止讲解

1. 图片、介绍、目录、地图与行程点击统一使用selectedPoiId；origin独立。缺图显示当前点缺图状态，禁止串用上一点照片。先检查现有映射、静态URL和图片加载，不从网上任意下载图片替换用户原图。
2. 地点详情立即显示现有可用介绍。仅有“目录收录”时，合并同一POI已有事实及出处，避免调用GLM重写才能显示文字。尚贤石可使用本包已查官网样例，按仓库现有schema接入，不能将整个样例文件盲目覆盖pois.json。只有名称时明确内容不足，不编造建筑史或开放时间。
3. 沿着一次点击检查：事件绑定→当前poiId和非空文本→voice enabled/muted→playFull/队列→TTS响应→音频URL/MIME→audio.play() Promise→playing/currentTime→角色状态。用同一traceId定位，报告真实断点，不能先假定是TTS供应商问题。
4. 用户主动点“开始讲解”时，应在同次交互明确启动语音，或就地显示可操作的“开启语音并播放”控件；不要让它因隐藏的全局开关而静默返回。若保留用户显式静音，解释状态并提供解除入口。异步TTS后浏览器拒绝播放时，捕获错误，保留已合成音频并显示再次播放入口，不能只更改按钮文字。页面展示“正在准备语音／正在播放／已停止／失败原因”，状态由实际音频事件驱动。

6. 停止时清当前音频和待播队列；讲解中选B时停止A，A迟到文本/音频不得复活。角色嘴形跟实际声音，暂停/停止/失败闭口。网络补充只能更新文字及来源，不得未经用户操作突然播放。

### 3.2 按问题选择来源

- 稳定历史、校园文化：本地资料充分则结束；不足查相关官方文章，再允许已登记的社区资料补充，并标明来源。
- 游览体验、拍照建议：以用户兴趣和已知地点为基础，可引用社区经验，不能包装成官方推荐或当季实时花况。
- 今日开放、预约、门禁、临时封闭：只由相关且适用于查询日期的官方依据确认；一个官网没答案可查另一个相关官方栏目，社区旧帖不能替代。
- 校园新闻：优先与行程或用户兴趣有关的新闻，显示发布日期；新闻发生不等于活动允许公众参加。
- 路线与距离：交给现有地图服务。网页位置描述、社区地图和模型生成文字不能成为已核验经纬度/入口或真实步行路径。

选取同一层最相关的2—3个来源，并发读取；不要将表中所有站点都请求一遍。对别名进行一次规范化，携带校区限定；不先让模型对每个来源各做一次“思考”。官方证据不足才用允许的备用层；两轮共享时间和请求预算。来源更快返回不代表更可靠；弱来源不能覆盖仍有效的相关官方证据。停止条件是证据足够支撑当前问题，不是搜到固定数量网页。

### 3.3 最小模块与工具

复用已有目录结构放置以下职责，不强制新建同名文件：
- SourceRegistry：加载source_registry.json，按意图、校区、可用性筛选来源。
- RetrievalPolicy / EvidenceRetriever：读本地索引、缓存、已登记网页和已配置搜索服务，传递总deadline、取消与预算。
- EvidenceFilter：去导航/页脚，校验标题与正文的地点、校区、时间、来源及转载关系；目录/image_only不能当足够介绍。
- CampusQueryService / AnswerComposer：合并有据内容，只做必要的一次模型生成，返回现有前端协议。

模型可用工具：get_poi(poiId)、search_local(query,campusId)、search_official(query,campusId,asOf)、search_supplemental(query,campusId)、get_trip_brief(stopIds,asOf)。全部绑定注册来源和已有数据，后端独立校验参数。不得让模型执行任意网址、生成poiId或用自然语言直接宣称地图/音频已成功。

普通聊天可用不证明中转网关支持function calling、供应商搜索或音频。先做最小能力检查并记录结果。支持tool_calls则保留工具执行链；不支持则后端分流检索后一次GLM生成，照常完成用户功能。智谱原生搜索是否可用与GLM聊天网关分开配置；缺搜索Key时仍能查询本地索引及已登记公开页面，明确覆盖范围，不伪称完成全网搜索。凭证只保留后端。

### 3.4 分级缓存、索引与有限自主

不引入向量数据库作为本轮前置条件。复用当前LocalKnowledge、别名与中文关键词索引；新增正文块随来源及poiId建索引即可。预热仅限本轮固定地点和有关公告入口，后台或显式维护命令执行，不能阻塞应用启动和首次点击；不全站递归爬取。

- 稳定资料缓存初值86400秒，新闻300秒，当前规则60秒；可配置。TTL只决定刷新，不证明当日适用。过期动态信息只能标为上次资料，不能当今日已核验答案。
- 结果缓存键包含校区、poiId、意图、查询日（Asia/Shanghai）、查询文本、必去/避开等约束、来源范围、数据版本。约束集合可排序，路线实际站点顺序不能随意排序。个性化完整回答不能跨用户无条件共用。
- 相同请求合并singleflight，复用连接池；一个订阅者取消不得取消其他订阅者还需要的共享请求，最后消费者退出再尝试取消上游。
- 失败15秒冷却，防止重复打不可用源；不能缓存成“无公告”。成功完成指定范围检索且没证据才允许30秒负缓存，并保留范围。
- 搜索先用于找相关正文；标题/搜索摘要只作线索，不独立支撑开放时间等结论。正文选最相关片段，不把首页导航、整站文本和长对话历史全塞给模型。

模型可以改写关键词、选择已注册工具并触发一次备用查询。不能新增无限检索循环或自行扩大到未核验域名；HTTP并发已经能并行查多个网站，不需额外多个模型Agent。

### 3.5 预算与前端状态

以retrieval_policy.json为默认：检索总预算3500ms，含排队、搜索、取页、提取；单来源至多1500ms；最多两轮、两次搜索、四次页面读取；总并发3、单域名2。实际超时取阶段配置与剩余预算的较小值，第二轮不能重新获得3500ms。失败请求计入次数，默认不自动重试。先用这些值测试，必要时按实测调整并记录。

默认程序按当前操作和已解析意图分流，通常一次模型生成；确需模型选择工具的路径最多两次模型调用。可选的模型工具选择须在联网检索阶段启动前完成，检索两轮之间不再插入模型思考。联网检索阶段启动时建立3500ms截止时间，并受请求开始时45000ms截止时间共同约束；前面的本地读取和可选模型选择仍计入整体耗时。整个回答45000ms仅为资源截止时间，不是提速成绩；检索与模型不能各自重置整条请求截止时间。8秒无正文时显示已有有据内容和可取消状态，不能把“正在查询”计作有效首正文。到期不再开始新调用，尽力取消在途请求；无法保证供应商已接收调用不计费，要如实报告。

沿用现有SSE/接口做最小兼容扩展。事件关联channel、requestId、generation、seq、campusId、poiId/routeId；地点详情、聊天、路线、ASR使用独立代际，普通选点不能误取消正在生成的有效路线。重规划、清空路线、换校区或使当前路线请求失效的起点变化必须更新路线代际，防止清空后旧线路重画；普通选点不更新路线代际。旧代际和乱序结果不可覆盖当前模块。查询状态区分success、partial、no_evidence、timeout、unavailable、cancelled、error；复合问题逐部分记录状态。

资料记录sourceId、注册来源registryId、标题、最终URL、publishedAt、validFrom/validTo、fetchedAt、校区/地点、官方或社区、原始发布者/转载关系。未知时间为null；抓取时间不冒充发布日期；模型只能引用实际证据ID。馆内规则与入校规则分别处理。不同来源冲突时解释冲突，不能单按发布时间或多数票覆盖。

行程使用draft/route_pending/ready/partial/failed；真实路径和必去约束未满足不得ready。地图实际应用回执由前端提供，服务端计算完成与前端画线完成分开；总成本不完整不得承诺时间可行。

本轮查到的“网上校史馆上线”可作近期线上参观建议，不能称为9月17日当天新闻；参观指南未显示发布日期时保留null并标为一般指南，不能保证当天开放。未检索到当天信息与抓取失败需区分；不把不相关科研新闻塞入出发注意事项。

加速按链路处理：点位介绍/短讲解走本地快路径；已知候选、必去/避开校验和可复用路线结果先渲染；官方补充和自然语言润色后续补齐。同一次规划不让GLM反复判断已经确定的ID；不为每个站点串行生成介绍。草稿先出现时明确其状态，真实步行未完成不能标为可出发；缺少总成本不能宣称满足时间上限。是否关闭模型思考或更换模型，必须先验证该网关支持并做小样本质量对照，不猜参数。

常用官方内容采用缓存与过期刷新，动态开放信息显示最近核验时间，过期数据不能当实时结果。复用现有图片映射、浏览器缓存与选中图加载，必要时只预取下一张，禁止加载全图库抢占当前图请求。

落实以下小步响应优化，并与改前同样本对照：
1. 当前点介绍和固定讲解本地直出；常见单一事实问题资料完整时可直接使用有来源的短答案，不强制GLM润色。一般问答/复合问题仍使用检索增强生成，逐部分处理时效性。
2. 结构化选项已确定的ID由程序校验，先生成可检查的行程草稿和已有介绍；路线请求与非关键的解说润色独立进行。缓存命中的路线直接应用；网络补充不阻塞已有照片或讲解。必去缺失和步行时间未知不能藏起来。
3. 模型上下文只保留当前任务、必要历史、相关资料和来源元数据；初值最多6段/6000字符，必要证据与时间条件优先保留。不得简单截掉后半句导致来源、否定或日期丢失。输出按用户问题控制长度，不降低事实完整性。
4. 确认前端消费真实SSE正文，检查代理/服务是否把流缓存到结束；状态、工具参数、推理内容和答案正文分离。前端可按帧/短间隔合并token更新，避免每个token重建地图、角色和整张行程；保持停止和交互响应。
5. 图片保持原图与原映射；当前选中图优先，非当前按需加载，保留尺寸避免跳动；只预取下一张已有图。缓存URL要稳定，有更新才换版本；不能把错误响应长期缓存。资源确实过大时生成派生缩略图并保留原图，不改地点绑定。
6. 短讲解直接TTS，复用文本/voice/语速对应音频缓存；沿用已有分句FIFO及限量预取，避免完整长文合成后才播。普通话ASR直接走音频适配器，不额外让GLM重写转写才显示。

测量定义必须一致：t_click→介绍实际DOM出现；t_play_click→第一段音频playing/currentTime推进；t_plan→首个可用草稿，以及t_plan→完整真实路线地图应用分别记录；t_record_stop→转写文字可编辑。另记录后端排队、本地检索、搜索、取页、模型首正文与生成完成、外部调用数量/缓存命中。服务日志用单调时钟；浏览器测performance时钟，不把客户端与服务端未经校准的时间戳直接相减。

本地充分命中的点位介绍可先设“热缓存点击到可见中位数≤300ms”为试验目标，失败如实报告；不是未经测试的承诺。TTS冷/热、图片冷/热、问答冷/热分开，同输入3次原始值和中位数；网络波动和失败都保留。真实模型首正文此前12.7—33.6秒，若本轮仍慢，报告具体模型/网关耗时，并将固定讲解与本地回答的收益单独说明，不能用几毫秒检索收益冒充整体大幅加速。不要为了达标把错误提示、占位句或不完整行程算有效结果。

## 5. 普通话语音转文字本轮落地

实现“点击录音→停止→识别成可编辑文本→用户发送→沿用原问答/路线流程”。只要求普通话，不加入唤醒词、长时间后台监听或新形象系统。先复用现有ASR适配器，核对实际供应商、鉴权、音频格式和配置；TTS的Edge服务不能代替ASR。若模型网关没有音频能力，ASR单独配置，不擅自把录音发给普通聊天接口。

前端使用浏览器麦克风权限与录音能力，协商支持的MIME；后端按实际ASR接口要求转换音频，不能只改扩展名。限制单次录音时长/大小，停止/取消/卸载释放麦克风。录音时暂停角色播音以免识别自身声音。权限拒绝、空录音、超时、未配置显示具体可操作状态；取消后迟到识别不覆盖新输入。识别结果允许修改，不未经确认自动执行路线。语音地名经现有别名和ID选项解析。

若确实缺少可用ASR凭证，完成适配、配置示例、错误反馈和录制夹具；明确“真实ASR仍缺配置”及最小需补字段，不能把录音波形/模拟转写标为已实现识别。不要因此停掉其他已授权修复。
