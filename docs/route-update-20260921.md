# 行程换站、起点与高德同步修复（2026-09-21，第二批）

基线：`fix/ip-route-autoplanning`，`026a508`。沿用现有行程、地图预算、照片轮播、语音与评委启动流程。本批工作区修改尚未提交或推送。

## 修复内容

- 换一批原先保留一个旧的可选站：只有一个可替换站时结果完全不变。现在优先换为未出现的候选；候选使用完后可轮换旧候选。必去、起终点、避开约束继续保留，时长、步行上限、无障碍等条件继续经过原有检查。固定站点占满计划时明确显示“没有可替换站点”，不会悄悄放宽条件。
- 我的起点仅保留定位一次、持续定位、在地图选择起点，以及现有目录生成的常用点位池。常用池独立于目录的分类和关键词筛选。停止定位、取消选点仅在操作中显示；持续定位沿用移动80米且间隔60秒的更新门槛。
- 草稿自动从所选POI起点匹配高德坐标，按站点顺序规划到终点，跳过起点到自身的无意义路段。未指定起点时优先使用已选地图位置，否则从首站出发。明确选择当前位置但定位失败时展示失败原因。
- “检查行程条件”改为“确认草稿并同步路线”，保留原有条件检查状态机。自动同步无需再次手动规划，提供加载进度和失败提示。地点切换不会清掉当前行程路线。
- 用户提供的 background.jpg 作为固定虚化背景，CSS blur(7px)及浅色遮罩保证文本可读。

- Node 前端/导航/语音/传输回归：83 passed；额外 interaction.test.mjs 9 passed。最后的界面微调再次运行8项页面回归，全通过。
- 真实Chrome和本机高德代理三轮端到端：起点第九教学楼、终点校史博物馆，必去第九教学楼、避开体育馆、步行上限30分钟。中间站依次为爱晚湖、北洋广场、冯骥才研究院，约10—12秒自动取得并显示全程实际步行线路，无需地图二次操作；页面异常0条。
